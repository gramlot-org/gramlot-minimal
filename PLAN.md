# Gramlot Standalone delivery status

Status date: 2026-09-16. Development branch: `develop`.

## Implemented and tested here

- CLI and safe/atomic output path.
- Python page discovery without executing application modules.
- TOML metadata and symlink containment for all project inputs.
- Bounded CSS/resource embedding with explicit unsupported-syntax diagnostics.
- Versioned JSON envelope restricted to opaque typed `application_data`.
- Narrow synchronous provider proposal, complete-profile declarations and offline report.
- Deterministic self-contained HTML assembly with CSP and base64 runtime encoding.
- Paired GS documentation and durable core port requirements.

## Blocked integration

The clean core currently contains documentation and port protocol, with no accepted
Python compiler, embedded Source hydration, offline resolver transport, runtime
bundle, typed shared-branch codec/atomic replacement, or multi-page/print/save
lifecycle. Therefore the default CLI cannot produce a working Gramlot application,
and real offline browser verification cannot run. This is an architectural blocker,
not a packaging fallback opportunity.

Resume by preparing and accepting the bounded ports in **GS-015**. Adapt or replace
the provisional provider seam to match accepted contracts. Then add a real Python
multi-page fixture and run the blocked-network browser gate before changing status or
claims. Direct PDF generation remains optional later; fillable PDF is not claimed.
